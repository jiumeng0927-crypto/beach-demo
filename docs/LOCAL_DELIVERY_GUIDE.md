# 潮汐沙岸：本地交付与稳定启动指南

## 1. 为什么不能直接双击 index.html

项目使用 ES Module、分包脚本和纹理资源。浏览器从 `file://` 打开时会受到模块来源和资源加载
规则限制，因此网页成品必须通过本机 HTTP 地址访问。开发阶段的 Vite 服务依赖终端进程；终端
关闭后，原来的 `localhost` 地址自然会失效。

本项目在生产构建中加入了无第三方依赖的 Node 本地服务器，使成品包不再依赖 Vite 终端。

## 2. 最简单的使用方式

1. 解压网页成品包。
2. 双击 `启动网页.cmd`。
3. 启动器检测服务并打开正确地址。
4. 使用结束后双击 `停止网页.cmd`。

默认地址为 `http://127.0.0.1:5175/`。如果端口已被其他程序占用，服务器会依次尝试
`5176` 到 `5195`，并打开实际成功的地址。

## 3. 稳定机制

- 服务只绑定 `127.0.0.1`，不暴露给局域网或互联网。
- 后台进程使用独立日志，不依赖启动命令窗口继续存在。
- `.tideline-server.json` 记录实际 URL、PID 和停止令牌。
- 重复启动先请求健康端点，已有实例正常时直接复用，不重复占用端口。
- 停止操作必须同时持有本地状态文件中的随机令牌。
- HTML 不缓存；带内容哈希的构建资源使用长期缓存。
- 模型、音频和大纹理支持 HTTP Range，便于后续导入资源。
- 非法路径和目录穿越请求会被拒绝。

## 4. 源码命令

```bash
npm run build
npm start
npm run status
npm stop
```

启动器专项回归：

```bash
npm run test:server
```

测试覆盖健康检查、MIME、HEAD、Range、路径安全、前端路由回退、重复启动复用和授权停止。

## 5. 状态与日志

- `.tideline-server.json`：当前后台服务状态，停止后自动删除。
- `.tideline-server.log`：后台启动及异常日志。

两者都属于运行时文件，源码版本控制和交付打包会忽略它们。若状态文件意外残留，下一次启动
会先验证健康端点；失效状态会被清理并自动创建新服务。
