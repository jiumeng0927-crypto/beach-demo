# 台球：观察状态、固定拉杆视角与录音音效

版本：0.43.0。日期：2026-09-14。作者：钱奕好。

## 本次问题

0.42 的俯视状态仍可按白球击球，观察与操作没有明确隔离；俯身拖动的横向位移改变 `viewYaw`，相机每帧继续插值，所以拉杆会转向。音效使用两个衰减正弦，容易产生不合适的音调。

## 状态与输入

| 状态 | 相机 | 球杆 | 结束条件 |
| --- | --- | --- | --- |
| 观察 | OrbitControls 自由环绕、缩放 | 隐藏，不接受击球输入 | 主动选择击球 |
| 击球准备 | 白球中心俯身，可微调方向 | 显示，可设置力度和杆法 | 按下画布开始拉杆 |
| 拉杆中 | 位置、朝向、target 和方向保持不变 | 纵向位移决定力度，横向位移忽略 | 松手击球，取消则不击球 |
| 走球中 | 自动回到观察，可转动镜头 | 隐藏，不接受第二杆 | 停球后仍需主动选择击球 |
| 自由球/裁定 | 俯视，沿用已有摆球和规则按钮 | 不接受击球 | 确认后保留观察 |

`BeachBilliardsGame.canAim()` 将 `cueView` 纳入统一门控，鼠标、触屏、按钮和 `shoot()` API 不能绕过观察状态。`getProgressState()` 对外给出 `interactionMode`，不另造第二份可分叉的布尔状态。

在 `pointerdown` 保存 `viewStartYaw`，`updateAim()` 只计算 `dy / 240`。拉杆期间拒绝方向微调，`BeachExperience.animate()` 停止相机跟随插值，同时不调用 OrbitControls 更新。不能只设置 `controls.enabled = false`，因为已有程序相机动画仍可能继续改位置。

取消处理复用 `cancelAim()`：释放 pointer capture、清零临时力度并隐藏提示。状态切换、Escape、失焦、pointercancel 和 lostpointercapture 均不会发射。成功一杆才播放击杆声并进入观察。

观察切换保留当前位置；台球观察最小距离暂设为 1，离开台球恢复全景的 8。切换时清除 OrbitControls 的阻尼残量并恢复原相机位置与旋转，避免切回观察后被旧拖动惯性或距离限制推走。普通场景导航仍使用原来的相机流程。

## 音源与处理

音源：[Za-Games / billiard ball clack](https://freesound.org/people/Za-Games/sounds/539854/)，作者页面标明 [CC0](https://creativecommons.org/publicdomain/zero/1.0/)。使用公开提供的 HQ MP3 预览（7515 字节），不绕过登录下载原始 WAV。文件和 SHA256 见 `public/audio/billiards/manifest.json`，运行时不访问第三方网站。

这是一段球碰球录音，不是四种独立实录。击杆、碰库和落袋由它做去直流、低通、包络和增益处理，明确作为设计衍生音；没有继续用合成正弦“叮”声。击杆偏短、球碰球更清脆、碰库降低高频和音量，落袋降低播放速率。它仍是简化声音设计，不宣称还原具体品牌球桌或皮头。

首次台球操作解锁 AudioContext 后，用 `decodeAudioData()` 解码并缓存四个 AudioBuffer。重复操作复用加载任务；8 秒超时、加载错误可重试；销毁时中断请求，迟到解码不能回填已销毁实例。素材未就绪时跳过声音，不补播过期事件，也不退回旧电子音。浏览器或系统静音仍会影响实际听感。

实际出杆、首次接触、落袋驱动物理事件音效。保留 12 路上限、主音量、压缩器、距离衰减、声像和碰撞对去重，不更改中八规则、袋口、碰撞体、摩擦或旋转。

## 验证与复习

- `npm test`：状态门控、原物理/规则、滤波数据、延迟加载、失败重试与异步销毁。
- `npm run test:billiards-presentation`：桌面 1440x900 与手机 390x844 的实际输入、观察白球拖动、切换取消、拉杆锁镜、真实解码 PCM、静音和模型资源释放。
- `npm run test:billiards-input`：连续两杆、指针捕获/取消、自由球、杆法与台呢控件。
- `npm run test:production`：发布根路径/子路径和素材可用性；使用生产 URL 再测交互。

首轮浏览器实测：桌面斜向拉杆并滚轮、手机斜向触摸拉杆，持续等待多帧后，位置/旋转/target/yaw 四项误差均为 0。四类录音衍生 PCM 峰值约 0.76 / 0.90 / 0.48 / 0.60，没有削波；实时音频图也检测到非零输出。自动测试不能替代用户音箱/耳机上的主观试听。

2026-09-14 完成全场景生产回归：桌面 126 次绘制 / 581738 三角形，手机 68 次 / 259561 三角形，无脚本错误、页面溢出，资源释放通过。台球专项、连续输入、NPC、发布根路径及仓库子路径音频解码均通过；20 组单元检查、88 个模块语法检查及依赖审计通过。

回归中曾发现旧测试直接写入相机位置，与台球重置触发的俯视过渡相冲突。改用正式的 `startCameraTween()` 并等待结束后再比较清晨灯光及泛光，原检查阈值没有放宽。这个案例说明：测试调整视角也要尊重相机的控制权，不能绕过应用的导航流程。

参考：[Three.js OrbitControls](https://threejs.org/docs/pages/OrbitControls.html)、[MDN decodeAudioData](https://developer.mozilla.org/en-US/docs/Web/API/BaseAudioContext/decodeAudioData)。项目实际使用 Three.js r160，修改前核对本地源码中的阻尼及距离约束逻辑。
