# 主沙滩、海滨街区与水面收敛 / 0.45.0

作者：钱奕好。日期：2026-09-15。项目：潮汐沙岸。

## 本轮目标

保留海岸、台球与拾取路线，在沙滩后侧增加沿海小街。场景采用低饱和灰绿、海蓝、珊瑚红与灰白墙面。商铺为项目自建的程序化建筑；桌椅和花箱为明确标注来源的外部模型，不能把两者混称为下载模型。

进入场景后，打开设置面板，点击“海滨小街”即可查看；重置视角回到原沙滩构图。也可转身或用漫步模式走到街边。商铺目前是外观场景，门关闭，没有室内、购买或车辆交通玩法。

## 地形与通行

- 道路中心为 `z = 65`，远端缓慢向内陆弯曲，在远景雾中延续；近段分为两条车道、人行道、路肩。
- 地形本身不削平。道路横断面取现有地形最高采样高度并抬高少量，形成可见路基；商铺地基覆盖原地形起伏。
- 根据后续需求，仅在屋后 `z > 84` 加入缓升地形，并将裸沙渐变为灰绿植被底色；18 簇折面叶片补出近处绿化轮廓。这里不是删除网格再用天空遮洞：底面保留，仍与外围网格逐点接续，海滩活动区高度不变。
- `createStreetProfile` 在近景密采样、远景稀采样。道路网格与相机地面查询使用同一组样本。
- 店前坡道按实际三角形插值，不能用双线性曲面替代两个平面三角形。专项射线检查对比可见地面与相机地面高度。
- 局部移开与道路、商铺及连接道相交的草；原沙滩主要物件不移动。仅向内陆扩展相机活动边界至 `z = 87`。
- 商铺、长凳、灯杆及导入模型有简化碰撞。屋檐和招牌不作为复杂精确物理网格。

## 建模与材质

`src/experience/CoastalStreet.js` 负责路面、建筑、店前坡道和昼夜发光。相同材质的建筑小部件合并，路面按空间拆成三段，避免整条街在海景视角始终绘制。路灯使用自发光灯罩，不新增四盏阴影灯；窗户为不透明有色 PBR 材质，夜间发暖光，不伪称真实室内透视。

马路线条与斑马线绘在路面着色器中，无额外悬浮平面，降低闪烁与绘制次数；线条边缘按屏幕导数抗锯齿。路肩实体连接到沙面。招牌是本地 CanvasTexture，不请求网络字体。

房屋补齐两个坡屋面下的山墙、前后檐口、雨水管、侧窗与窗台、遮阳支架。咖啡店增加临窗吧台，小铺增加陈列架，冲浪店保留板架。山墙由 ExtrudeGeometry 生成，合并到 BoxGeometry 建筑批次前先转为同样的索引格式，否则 mergeGeometries 会失败。建筑仍为封闭外观模型，不含室内营业玩法。

屋后叶簇采用折叠的叶片几何、实例颜色和低幅风摆，按空间分为三批，可在海景视角裁掉。移动端使用更少叶片、较稀道路采样和屋面接缝。为减少重复噪点，沙草改为移动端 70 簇、桌面端 300 簇；随机石子改为 36/76，贝壳改为 16/30。新增植被不新增阴影绘制，保留原渲染预算。

对不投射阴影的街区物件采用紧贴模型的包围盒裁剪；细长道路和植被批次的包围球会把大量屏幕外空间也算进来。仍投影的物件不套用主相机可见性裁剪，避免画面外物体的阴影突然消失。新增叶簇使用原有风力/相位，风停时不会自行继续摆动。

## 主沙滩布局

- 中后部和东侧保留四张条板躺椅，并保留一组外部桌椅模型。大型帆布休息棚会遮住沙滩纵深，已直接删除。
- 全场保留原有三把遮阳伞。后加的东西两把重复遮阳伞已删除，避免伞面在远景中形成连续遮挡。
- 栈道附近 `(31, 43)` 增加带爬梯、横撑、栏杆和红白救生圈的瞭望点；这是景物，不是可攀爬关卡。
- 店前增加一组咖啡桌椅和两只陈列木箱。导入模型共 23 个实例，仍使用八类本地模型文件，不增加线上依赖。
- 主沙滩原有船、台球、栈道与收集点不移动。躺椅与瞭望点有简化碰撞，局部清理草丛；测试检查保留设施不覆盖 18 处收集点。

家具沿用 `CoastalProps` 的顶点颜色、材质合并、反射排除和统一释放流程，不逐条木板增加 draw call。店前模型在画质切换后重新对齐坡面，同时更新实例矩阵、包围盒、草地避让体积和碰撞高度，避免只移动可见模型却留下旧碰撞体。

## 光影调整

四个时间预设都降低了主方向光，增加半球天空补光，同时减少会把阴影整体抬灰的环境光。曝光小幅提高，用较柔的亮部换取屋檐、躺椅和沙丘阴影中的颜色层次。高画质仍使用 2048 阴影图与 PCF 软阴影；阴影相机范围收紧，`normalBias` 提高到 `0.035`，高画质阴影半径为 `3.2`，减少贴面条纹和过硬边缘。色调映射继续使用 ACES，不额外增加实时灯或后处理成本。

为给主要设施保留预算，将救生圈从 3500 减到 1399 三角形，装饰贝壳从 2200 减到 799，保留 PBR 贴图。可用 `npm run prepare:small-props` 从经哈希校验的现有 GLB 执行这一步；达到预算后再次运行不重复减面。素材清单记录上一份网页模型哈希及处理步骤，不覆盖原始来源信息。

## 游客与动画

原有小林和阿辰继续负责拾取任务及台球引导。新增咖啡店常客阿梅、冲浪爱好者阿浩，以及在人行道往返的小帆和小乐，共六位游客。巡逻端点驻足两秒，对话和漫步玩家靠近时暂停，位置、脚底高度和相机碰撞体同步更新。当前为固定人行道路线，不是全场景导航网格或自动过街系统。

两份新增 `*-crowd.glb` 各 1473 三角形，共 306468 字节，由原有已校验的 Quaternius 衍生游客在 Blender 中焊接、减面生成，保留顶点颜色、骨骼与 Idle / Walk / Victory。四个不同 GLB 只加载各一次，通过 SkeletonUtils 克隆为六个实例；几何与材质共享，骨骼和 AnimationMixer 独立。释放时按资源集合去重，不能逐人物重复销毁共享几何。

```bash
npm run prepare:crowd
npm run test:ocean-npc
npm run test:street
```

`prepare:crowd` 只读取公开目录内经哈希校验的两份基础 GLB，不依赖旧角色参考图；需要本机 Blender。完整 `prepare:npcs` 在基础模型准备后也会生成两份轻量版本。生成结果与来源记录均写入 NPC 资产清单。

## 水体修正

Three r160 会把 `fogColor` 转为当前渲染目标的输出色彩空间。旧水体在进行线性光照合成时提前混入该值，随后再次色彩转换，造成远海亮带。现在在色调映射与输出转换后处理这段雾，顺序与内置雾一致。参考 [Three.js 色彩管理](https://threejs.org/manual/en/color-management.html) 与仓库安装版本的 `WebGLMaterials.refreshFogUniforms`。

细波纹理中交换 UV 轴的层同步交换法线分量；细节根据像素覆盖的世界空间面积淡出，避免掠射角处过密碎纹。白沫综合风力、波峰、陡峭度和水深，仅做实时近似，并非流体求解或虚幻引擎水系统。

## 手动发布

继续使用 `npm run export:web` 更新根目录网页快照与 `dist`；手动上传 `dist` 内的内容，保留素材与许可文件。本轮不会自动提交或推送 GitHub，也不修改已暂存内容的暂存状态。开发入口仍为 `dev.html`，不要将根目录成品 `index.html` 改成源码入口。
