# 潮汐沙岸：场景边界学习记录

作者：钱奕好。版本：0.44.0。日期：2026-09-14。

## 这次修复什么

从沙滩侧面看，远处沙地突然结束，海面露出斜着的矩形边，后面只剩天空。用户红圈标出的是可见几何边界，不是人物或相机的移动限位。本次不调整中央场景布局，也不修改台球规则和拉杆锁镜逻辑。

旧沙地的世界范围为 X=[-130,130]、Z=[-15,105]；海底范围为 X=[-130,130]、Z=[-195,-15]；海面范围为 X=[-600,600]、Z=[-1045,40]。即使相机没有走出活动区，也能从侧面看到这些有限平面的外边。

## 几何补接

实现位于 `src/experience/CoastBoundary.js`，由 `world.js` 创建、持有并释放。沿原沙地和海底的外周，直接读取边缘顶点及法线，变换到世界坐标，再连接四层渐疏的外围环。接缝不重新采样，避免两边顶点不对应产生细缝或 T 形接点。

原来的沙地、海底和泡沫顶点及三角形顺序保持不变。尤其不能只把泡沫抬高后换一张不同密度的网格：顶点看似贴合，三角形内部仍可能相交。

外围沿岸保留密集的纵向采样；较远处只保留宽缓地形。把高频沙纹高度直接采到大网格上会生成棱角明显的海湾，因此先延续原边缘轮廓，再渐变到宽缓起伏。水下坡面继续向外延伸，避免深度折射在旧海底尽头失去地面。

新增地形为一个网格，与原沙地共享世界坐标 PBR 材质。高档增加 5584 个三角形，低档增加 3808 个；排除在水面镜像反射之外，但参与主画面和折射颜色/深度采集，不额外生成贴图。画质切换和退出沿用原场景的唯一资源释放流程。

## 远海与地平线

`OceanWater.js` 只拉开 |X|>160 和 Z<-180 的外围采样，近岸原始位置和总顶点数不变。X 两端、海面远端及外围地形延伸至 3600，超过相机 1800 的远裁剪距离，并为允许的相机移动留出余量。这仍是有限场景，不是无限世界，也不扩大可玩区域。

海浪用相邻顶点的实际距离计算 `oceanSpacing`。外围网格被拉大后，旧间距不能继续使用，否则无法解析的短波会把远处三角形抬成尖片。

仅延长网格仍不够：远裁剪以外会显示天空，若天空与地面雾色不同，仍会有硬线。天空地平线因此使用 Three.js 自身的 `fogColor` uniform，交给渲染器按当前输出色彩空间更新。不要将线性 RGB 直接混入已经转换的屏幕 RGB。没有雾的独立 HDR 环境光场景不启用这段混合，保留原照明。

## 手机岸线条纹

降低折射目标分辨率后，直接读取最近深度像素会把阶梯状深度与连续的水面深度相减，产生周期性的干湿条纹。隔离测试中，关闭泡沫或几何波浪都无法消除，改用纯色水面则不出现，说明问题来自光学深度采样。

保留深度贴图的最近点采样，在 GLSL 内读取相邻四个像素，先重建当前屏幕位置的窗口深度，再线性化为相机距离。显式使用 `uRefractionTexelSize` 跟随目标尺寸更新，避免依赖不同设备的硬件深度过滤行为。原来的前景遮挡排除逻辑保留。代价是每次深度查询由一次变为四次纹理读取，不增加渲染通道或目标分辨率。

专项测试用 GPU 渲染 8x8 平面深度，再放大到 61x53；同时对比重建和旧最近采样的误差。此外验证外围地形确实被画入折射目标，不只检查可见标志。

本机桌面和手机测试中，编码后的重建最大误差为 0，旧最近采样对照达到 255；这是放大 100 倍后写入 8 位颜色通道的测试值，不代表浮点运算绝对无误差。水陆边缘的实际截图同时复核。

## 验证方法

```bash
npm test
npm run test:boundary
npm run test:swash
npm run test:water-layout
npm run test:water-quality
npm run test:visual
npm run build
npm run test:production
```

`boundary-unit-check.mjs` 检查两档画质的接缝、三角形朝向、边连接次数、射线覆盖、包围盒、近海采样和三角形数量。`boundary-check.mjs` 在桌面 1440x900、手机 390x844，从东、西、内陆、远海四个方向实际渲染，检查画布亮度、页面溢出、运行时地面覆盖以及切档/退出只释放一次。

NPC 回归另固定被测画质，避免无头浏览器负载触发自动降档后比较不同档的碰撞数量；模拟按 E 前等待对话框 close 回调清空 activeId，并先让相机落地。原先只看到 open 属性消失就立即按键，存在事件时序竞态，不修改 NPC 运行逻辑来迎合测试。

截图和结果在 `screenshots/boundary/`。原生产版对照保存在本地 `tmp/boundary-before/`，不进入公开源码。用 `TIDELINE_URL=http://127.0.0.1:5175` 可检查真正运行中的构建，而不是误测另一份开发源码。

默认入口仍采用原有桌面 650000、移动端 270000 的多通道渲染三角形预算，不提高阈值。侧面视角因可见物体更多，旧版移动端已达到约 274190/277314；本次对应值约 281806/284930，不应将入口预算测试描述成所有视角都低于 270000。

2026-09-14 最终验证：22 个逻辑套件、93 个 JS/MJS 语法检查通过；边界、泡沫、水体布局、水质、NPC、台球视听、完整画面，以及 dist/根目录快照的根路径和子目录发布测试通过。完整画面桌面为 128 次绘制、592906 个三角形，手机为 70 次、267177 个三角形；控制台错误和页面溢出均为 0，资源释放检查通过。npm audit 当次报告 0 个已知漏洞，不代表永久安全保证。

## 学习练习

1. 用同一相机拍摄修改前后图，区分“几何没铺到”“背面被剔除”“雾色接不上”三类问题。
2. 检查索引网格的内部边应被两个三角形共享，只有内外周界允许出现一次。
3. 修改远景采样间距时，同步检查波形过滤、包围盒和移动端开销，不要只改变平面尺寸。

## 当前源码和手动发布

后续以 `E:/桌面/Beach demo` 为准。用户保留手动上传网页成品，不启用自动部署。`dev.html` 是源码入口，Vite 开发根路径映射到它；根目录 `index.html` 是手动发布快照。`npm run export:web` 构建最新 dist 并更新根目录快照，不删除旧文件、不上传网络。具体步骤见 `docs/MANUAL_PUBLISH.md`。

参考：[Three.js BufferGeometry](https://threejs.org/docs/pages/BufferGeometry.html)、[FogExp2](https://threejs.org/docs/pages/FogExp2.html)。项目使用 r160；色彩空间行为以已锁定版本的 `WebGLMaterials.js` 为准。
