# 海滨订单、NPC 关系与社区声望 / 0.48.0

作者：钱奕好。日期：2026-09-15。项目：潮汐沙岸。

## 本轮目标

`0.47.0` 已经用每日委托串联多个玩法，但拾取物进入库存后仍主要通过“出售全部”统一换钱，十位 NPC 的长期反馈也只有固定对话。本轮在不移动场景、球桌、商铺和拾取点的前提下，增加海滨订单与社区声望，使同一件物品出现“立即寄售”或“等待更高价订单”的选择。

## 每日订单

订单与海岸自然日同步，每日三项，三日循环。每项订单由具体 NPC 发布，要求一种物品与固定数量：

| 轮换 | 发布者 | 示例需求 |
| --- | --- | --- |
| 第一日 | 小林、宁宁、阿冉 | 海玻璃配色、贝壳陈列、净滩瓶罐 |
| 第二日 | 小屿、青青、小帆 | 小铺橱窗、咖啡桌摆件、步道回收 |
| 第三日 | 阿梅、阿浩、小乐 | 杯畔拾光、冲浪架装饰、旅途轻装 |

定向订单的基础报酬高于同数量普通寄售。交易页显示发布者、需求、实际结算价、库存是否充足和当日完成状态。玩家也可以直接与对应 NPC 对话交付；两个入口调用同一业务方法，不会产生两套库存规则。

## 原子结算

`CollectionCampaign.deliver()` 同时验证物品类型、数量、奖励和当前库存。验证通过后，在一次状态变更中扣除库存并增加潮贝，再统一持久化。UI 禁用按钮只是操作提示，真正的防重复、防负库存和余额上限仍在业务层。

订单完成状态只有在库存结算成功后才写入。若回调失败，订单保持未完成，玩家不会丢失物品。交付还会发送 `markettransaction`，因此现有“向小铺交付物品”类委托能从订单行为获得真实进度。

## NPC 关系与声望

每天第一次与某位 NPC 见面，该 NPC 的熟悉度增加 1；同一天反复开关对话不会刷分。完成其订单再增加 2。关系称呼分为“初次相遇、见过几面、熟悉朋友、亲近伙伴”，显示在 NPC 名册和对话身份中。

所有 NPC 熟悉度之和构成社区声望：

| 声望 | 等级 | 每份未结算订单加成 |
| ---: | --- | ---: |
| 0 | 初来海岸 | 0 |
| 4 | 熟面孔 | 2 潮贝 |
| 10 | 海岸帮手 | 4 潮贝 |
| 18 | 潮岸伙伴 | 6 潮贝 |

订单在真正交付时锁定结算金额。之后即使声望升级，已经完成的旧订单仍显示当时到账的金额，不会追溯性变化。

## 状态边界

`CoastalCommunity` 是不依赖 Three.js 的纯状态模块。它保存逻辑海岸日、各 NPC 熟悉度、今日已见角色和今日已完成订单，存档键为 `tideline.community.v1`。载入时只接受已知 NPC、当前轮换中的订单和有限范围的整数熟悉度；损坏或被拒绝的存储不会阻断场景。

跨日只清空“今日已见”和“今日订单”，永久关系继续保留。刷新则恢复当前逻辑日，不重复发放见面关系，也不允许重复交付。

## UI 与对话

交易页在余额下方增加社区等级、下一等级进度和今日订单。订单、普通库存出售与小铺商品仍在同一个滚动面板中，手机端不引入横向表格。NPC 对话会说明自己当天的具体需求；库存足够时出现交付命令，完成后文案和按钮立即同步。

## 验证

```bash
npm test
npm run test:living-coast
npm run test:visual
npm run export:web
npm run test:production
```

确定性测试覆盖每日首次见面、未知 NPC、防重复、库存不足、原子扣货、奖励到账、个人关系、总声望、等级奖励、历史结算锁定、跨日轮换、刷新恢复、损坏与拒绝存储。浏览器测试通过真实 NPC 对话交付海玻璃订单，检查库存从 6 变为 4、到账 20 潮贝、普通出售余量、购买商品、刷新后的订单与关系，以及桌面和手机布局。

学习练习：增加需要两种物品的组合订单；为不同 NPC 设计偏好的潮汐或时段；让高关系角色提供一次无报酬的剧情委托；比较“固定三日轮换”和“基于存档随机种子”的可测试性。

## 手动发布

运行 `npm run export:web` 构建 `dist` 并同步仓库根目录网页成品。当前发布方式仍由 GitHub Desktop 推送，不在脚本中保存账号或令牌。
