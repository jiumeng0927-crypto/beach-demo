# 原场景建模细化学习记录

0.35.0 的外部真实模型、岸石替换与新增布景见 [模型接入学习记录](COASTAL_ASSETS_GUIDE.md)。共用色板、棕榈弧线、曲面冲浪板、伞边和支架细化见 [柔和半写实画风规范](COASTAL_ART_DIRECTION.md)。以下保留 0.34.0 基础几何建模过程，便于比较程序建模与外部资产的差异。

版本 0.34.0，2026-09-09。学习者：钱奕好。保留小船 (14,20)、躺椅与遮阳棚 (-13,27) 的世界位置、旋转和缩放，以及原栈道路线。地形、岸线、棕榈位置和角色开关不改动。本轮重点是结构连接、轮廓、落地和模型渲染成本，不是增加人物。

## 小船

`createHullGeometry` 用闭合 CatmullRom 曲线作为平面轮廓。高档取 48 段、低档 32 段，在船底、下船帮、上船帮、船沿与内舱建立多圈截面，用索引连接。内舱不再是一张贴在船沿高度的平板，而是降低到局部 y=0.115。0.34.0 将龙骨局部深度调整为 -0.82 并封闭底部：保留整个船组原有变换，使船底稍嵌入沙面，避免漂浮。

`createFishingBoat` 合并横向肋骨、舱底木板和座板，共享木材材质。船体拥有更连续的表面和真实内外厚度；仍是轻量教学模型，并非测绘船模。救生圈、船桨和原有变换保留。

## 躺椅

`createDeckChair` 通过两端点计算支撑杆的长度、中点和旋转方向。两侧交叉腿、扶手、横梁合并为一个木框 Mesh。

布面沿四个控制点形成从座面到靠背的曲线，再加入横向轻微下垂。修改顶点后调用 `computeVertexNormals()`，使光照随弧度变化，而不是只旋转一张平面。

## 遮阳棚

四根立柱位置保持不变，新增斜向支撑并合入原木框。棚布网格从 12×4 细化为 24×12，保留整体拱形并加入小幅褶皱。条纹材质继续复用，不新增外部下载。

## 性能与检查

### 0.33.0 增量

- 座板加入 RoundedBox 倒角，下降至船沿下方并增加六处支撑，避免悬空；内舱面朝上，修复背面剔除方向。
- 船桨叶片以二次曲线轮廓挤出，加入轻微倒角，不再是矩形木块。
- 躺椅木杆使用轻量倒角，仍以两端点求旋转并合入同一 Mesh。
- 遮阳棚前后补下垂布边，沿原拱面接合；与棚布共享材质并合并绘制。
- 球台建模与碰撞共用袋角参数，台面真正开孔，袋口有内壁、底和袋唇。见 `BILLIARDS_PHYSICS_GUIDE.md`。

0.33.0 的整站基准桌面为 101 次调用 / 163239 三角形，手机为 47 次调用 / 56406 三角形。

### 0.34.0 栈道结构

原路径长度约 24.78 场景单位，固定 0.5 深度木板留下过大的间隙。现在按 `spacing = path.getLength() / plankCount` 计算间距，木板深度为 `spacing * 0.94`。高档 32 块约 0.728 深，低档 24 块约 0.970 深，两个档位都连续覆盖同一路线，只留窄缝。

通过八点略不规则 Shape 挤出木板，保留薄倒角；实例轻微宽度、角度和颜色变化打破机械重复，仍只有一个木板 InstancedMesh。板下两条承重梁沿同一路径挤出，立柱带柱帽，碰撞和漫步表面同步使用路径采样数据。

扶绳每一跨采用 QuadraticBezierCurve3，将中间控制点降低 0.25，形成轻微垂落；所有跨组成 CurvePath，再生成同一条 TubeGeometry。柱上的环形绑绳与扶绳合并，避免每个绳结增加一次绘制。

`clearVegetation` 只把位于栈道占地范围及安全边距内的草移到最近路肩，保持随机序列不变，因此其他草丛不会重新随机分布。测试确认两档均没有草丛中心留在步道表面。

木纹使用 `createWoodMaterial({ grainAxis: 'x' })` 对齐木板长轴，去掉重复的零星油漆点。新增参数默认仍为原来的 y 轴，不改变其他木件的着色方式。Shader 缓存键包含方向，避免同材质类型错误共用变体。

### 0.34.0 小船与躺椅

- 船舷增加三道沿轮廓的细分层接缝，与船沿合并绘制；内舱增加盘缆和连接绳。
- 船桨降低到船沿附近，避免悬空；底部封口与落沙关系有数值测试，中心龙骨约嵌沙 0.008 场景单位。
- 躺椅转轴位于两根交叉腿的交点；补扶手立撑、两侧布边和上下卷布，布面仍沿原曲线变化。
- 木件倒角用 Three.js ConvexGeometry 从每角三个内缩点构造低面数凸体，再按已有两端点算法定向。相比通用圆角箱体细分，平整木面不需要多余网格；保持倒角与原尺寸。

### 0.34.0 成本控制

首次增加细节后，桌面基准曾达到 173231 三角形，超过原 165000 上限。因此没有扩大测试预算，而是继续减去重复成本：

- 船体仍参加水面反射，但船内座板、桨、缆绳和救生圈等细部，以及干沙上的躺椅，不重复提交镜像通道；主画面中始终完整显示。
- 栈道底梁与木板一样跳过水面反射；船沿的细小分层不额外绘制阴影，厚船体继续提供轮廓阴影。
- 船体/船沿按质量取样；木件使用紧凑倒角拓扑，绳索分段根据可见尺寸控制。

0.34.0 整站基准包含水面镜像通道：桌面 95 次调用 / 164743 三角形，手机 42 次调用 / 54966 三角形。原测试上限仍为桌面 112 / 165000、手机 56 / 64000。桌面三角形接近预算，后续继续加模型时应先检查可见细节与合批成本。

运行 `npm run test:models` 可检查九个关键几何、有限顶点、地标坐标、铺板比例、船底与沙面的关系、草丛避让及资源单次释放。另对八个新增反射排除对象逐一检查：镜像通道隐藏、主画面恢复，并确认船壳保留在反射中。它还生成桌面/手机各四张不含 UI 的近景图，路径为 `screenshots/model-*-*.png`。之后运行完整 `npm run test:visual`，确保反射恢复、视角、天气、台球和画质切换没有回归。

- 局部细节优先合并同材质几何，避免每一根木条增加一个绘制调用。
- Three.js BufferGeometry 支持 `setXYZ`，不要假设存在任意命名的分量方法。
- 查看顶点法线、内舱深度、座面与横梁衔接，以及不同镜头下是否穿插。
- 移动端仍使用既有低画质策略。主画面新增局部网格，通过合批和反射剔除控制整帧成本，不能只按主场景 Mesh 数推断 Draw Calls。
- `screenshots/DetailedFishingBoat.png`、`DetailedCanvasDeckChair.png`、`WeatheredBeachShade.png` 为近景学习截图；桌面/手机整体图为 `*-beach-models.png`。

练习：只改躺椅 sling 曲线中一个控制点，观察座面弧度与网格法线；不要改世界坐标。之后运行 `npm run test:billiards-input` 重新生成近景截图，再执行整站视觉回归。

测试记录：夜景采用指数渐变，固定等待 1.4 秒不保证星光透明度已经达到目标。视觉测试现等待真实透明度、可见性和点数满足原条件后取图，并设 10 秒超时；不把采样过早误判成画质重建错误，也不放宽验收阈值。
