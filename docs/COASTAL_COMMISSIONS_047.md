# 每日海岸委托与跨系统事件 / 0.47.0

作者：钱奕好。日期：2026-09-15。项目：潮汐沙岸。

## 本轮目标

已有潮汐、拾取、交易、台球、天气、漫步和相机收藏都能独立运行，但玩家缺少把这些内容串起来的短期目标。本轮新增每日海岸委托，不移动沙滩、商铺、球桌、NPC 或拾取点，只在现有系统之上增加一层可轮换的玩法组织。

## 三日轮换

每个海岸日提供三项委托。自然时钟跨日时自动切换下一组，第三日结束后循环：

| 海岸日 | 委托 | 实际完成条件 |
| --- | --- | --- |
| 1 | 低潮巡查、沙滩热身、暮色构图 | 进入低潮带；完成两次有效击球；黄昏保存一个相机机位 |
| 2 | 潮线拾遗、小铺交付、雨中巡岸 | 拾取两件物品；出售两件物品；下雨时实际漫步十五秒 |
| 3 | 落袋练习、海滨来客、低潮巡查 | 打进一颗目标球；购买一件商品；进入低潮带 |

任务完成后不会直接改写余额。玩家在“海岸图鉴 / 委托”页领取奖励，潮贝仍由 `CollectionCampaign` 统一管理，上限和存档校验规则不变。

## 事件驱动

`CoastalCommissionBoard` 不依赖 Three.js，也不直接读取场景对象。它只接收标准化事件：`collect-item`、`sell-item`、`buy-item`、`billiards-shot`、`billiards-pocket`、`sunset-bookmark`、`low-tide` 和 `rain-walk-second`。

`BeachExperience` 负责适配现有模块：监听拾取与交易的 `CustomEvent`、台球的击球与落袋事件、相机收藏事件，并把环境状态转换为低潮和雨中行走进度。这样任务核心可以在 Node.js 中做确定性单元测试，渲染系统仍只负责画面与输入。

出售事件携带真实售出数量，而不是一次点击只记一次。落袋事件忽略白球。暮色构图同时检查“保存”动作和当前时钟区间。雨中巡岸必须满足下雨、漫步模式、角色落地且有水平速度，并按整秒累计，避免站着不动刷进度，也避免每帧写入本地存储。

## 存档与时间

委托使用独立键 `tideline.commissions.v1`，保存逻辑日序号、当前轮换进度和已领取状态。载入时只接受当前轮换中的合法任务，并把进度限制在目标值内；损坏 JSON 或浏览器拒绝存储不会阻止场景启动。

自然时钟本身从中午开始。委托板把已保存的逻辑日作为起点，再叠加本次会话经过的海岸日，因此刷新不会把进行中的委托强制退回第一日。手动选择清晨、日光、黄昏或月夜只改变时刻，不伪造跨日。

## UI 与 NPC

图鉴弹窗由两个页签扩展为三个同级页签：“图鉴 / 交易 / 委托”。`CollectionJournal` 通过 `data-collection-tab` 和面板映射统一切换，不再假设只有两个固定索引。委托列表显示条件、实时进度、奖励和领取状态；手机端沿用现有自适应列表宽度。

潮岸小铺店主会报告今日完成数量，并可直接打开交易或委托页。NPC 对话仍先关闭当前原生对话框，再异步打开图鉴，避免两个 modal 同时争抢焦点。

## 验证

```bash
npm test
npm run test:living-coast
npm run test:visual
npm run export:web
npm run test:production
```

单元测试覆盖三日轮换、目标封顶、未完成拒领、重复领取拒绝、奖励回调、刷新恢复、坏存档和拒绝存储。浏览器回归从真实低潮状态、台球事件和黄昏相机收藏完成首日三项任务，检查委托页、刷新恢复、领取后余额，以及桌面和手机布局与资源释放。

学习练习：新增只在大风时完成的摄影委托；让某项委托同时要求“低潮且黄昏”；为已完成但跨日未领取的任务设计补领规则；比较自动领奖和手动领奖对玩家反馈与存档边界的影响。

## 手动发布

运行 `npm run export:web` 会构建 `dist` 并同步仓库根目录网页成品，继续适配当前 GitHub 手动上传方式。命令不会提交或推送远程仓库。
